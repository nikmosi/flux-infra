# Immich Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Развернуть Immich в кластере Kubernetes через Flux CD с надежным хранилищем медиа на Longhorn (100Gi), отдельной БД CloudNativePG с расширением pgvecto.rs и регулярными бэкапами базы в S3 (Barman).

**Architecture:** Инфраструктура конфигурируется декларативно в Flux GitOps. Секреты S3 и БД шифруются через SOPS (age). Создается кластер CNPG `immich-postgres` с расширением векторов и Barman S3 backup configuration. Деплоится HelmRelease `immich` (`oci://ghcr.io/immich-app/immich-charts/immich`) с Ingress `immich.xinfra.ru`, Traefik Middleware (безлимитная загрузка) и PVC `immich-library`.

**Tech Stack:** Flux CD v2, Helm, CloudNative-PG (PostgreSQL 16 + pgvecto.rs), Longhorn CSI, Traefik IngressRoute/Ingress, SOPS + age, S3 (twcstorage.ru).

**Spec:** `docs/superpowers/specs/2026-10-12-immich-design.md`

## Global Constraints

- Domain: `immich.xinfra.ru`
- TLS Secret: `wildcard-xinfra-ru-tls`
- Namespace приложения: `apps`
- Namespace базы данных: `database`
- S3 Endpoint: `https://s3.twcstorage.ru`
- S3 Bucket: `a353ae34-e55f-4d81-b4fd-902fffed4427`
- S3 Region: `ru-1`
- StorageClass: `longhorn-low`
- Library Volume Capacity: `100Gi`
- SOPS encryption regex: `^(data|stringData)$` с публичным ключом age из `.sops.yaml`

## Review Focus

1. Проверка SOPS шифрования: секреты не должны утечь в Git в открытом виде.
2. Проверка Kustomize build: все сгенерированные манифесты должны корректно собираться и валидироваться.
3. Проверка параметров CNPG: правильный образ `ghcr.io/tensorchord/cloudnative-pgvecto.rs:16-v0.8.4` и preloaded библиотеки `vectors.so`.
4. Traefik Middleware: наличие middleware для отключения буферизации / лимита размера запроса.
5. Зависимости Flux: `immich` HelmRelease должен содержать `dependsOn: cnpg`.

### Task 1: Подготовка зашифрованных секретов Immich и S3 бэкапа

**Files:**
- Create: `clusters/my-cluster/secrets/immich-s3.enc.yaml`
- Create: `clusters/my-cluster/secrets/immich-db.enc.yaml`

**Interfaces:**
- Produces: Kubernetes Secrets `immich-s3-backup-creds` и `immich-db-user` в namespace `database`

- [ ] **Step 1: Сформировать манифест секрета S3 креденшлов для CNPG Barman и зашифровать через sops**
  Создать Secret `immich-s3-backup-creds` в namespace `database` с ключами `ACCESS_KEY_ID` и `SECRET_ACCESS_KEY`. Зашифровать через `sops -e`.
- [ ] **Step 2: Сформировать манифест секрета базы данных и зашифровать через sops**
  Создать Secret `immich-db-user` в namespace `database` с ключами `username: immich` и сгенерированным безопасным `password`. Зашифровать через `sops -e`.
- [ ] **Step 3: Проверить, что секреты расшифровываются и валидны**
  Запустить: `sops -d clusters/my-cluster/secrets/immich-s3.enc.yaml` и `sops -d clusters/my-cluster/secrets/immich-db.enc.yaml`
  Ожидается: корректный вывод yaml без ошибок.

### Task 3: Создание HelmRelease Immich, PVC и Traefik Ingress

- Consumes: `immich-postgres-rw.database.svc.cluster.local:5432`, `immich-db-user`

- [ ] **Step 1: Создать манифест `immich.yaml`**
  Описать:
  - `PersistentVolumeClaim` `immich-library`: storageClass `longhorn-low`, 100Gi, `ReadWriteOnce`.

    - chart `oci://ghcr.io/immich-app/immich-charts/immich`

    - Включение встроенного Redis subchart
    - Подключение внешней БД `immich-postgres-rw.database.svc.cluster.local` с реквизитами из секрета
    - Настройка `server`, `machineLearning` (с ограничениями CPU/RAM)
    - Ingress с хостом `immich.xinfra.ru`, TLS `wildcard-xinfra-ru-tls`, Traefik аннотациями для middleware
- [ ] **Step 2: Добавить `immich.yaml` в `clusters/my-cluster/releases/apps/kustomization.yaml`**
